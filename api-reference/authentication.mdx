Every request to the NDAPI must be authenticated using an API key. Keys are issued per environment — you receive a separate key for sandbox testing and for live production traffic. There are no sessions, cookies, or OAuth flows; authentication is stateless and handled entirely through a single HTTP header on every request.

## Authentication Method

NDAPI uses **Bearer token authentication**. Pass your API key in the `Authorization` header on every request:

```
Authorization: Bearer <YOUR_API_KEY>
```

Requests sent without this header, or with a key that is invalid or revoked, are rejected before they reach any endpoint logic.

## API Key Formats

Your API key's prefix tells you which environment it belongs to:

| Environment | Prefix | Example |
|-------------|--------|---------|
| Production  | `ndapi_live_` | `ndapi_live_xxxxxxxxxxxxxxxxxxxx` |
| Sandbox     | `ndapi_test_` | `ndapi_test_xxxxxxxxxxxxxxxxxxxx` |

You can find and rotate your API keys in the **Settings → API Keys** section of your NDAPI dashboard.

<Warning>
  Live keys (`ndapi_live_...`) only work against the production base URL (`https://api.ndapi.io/v1`). Sandbox keys (`ndapi_test_...`) only work against the sandbox base URL (`https://sandbox.ndapi.io/v1`). Using a key in the wrong environment will return a `401 INVALID_API_KEY` error.
</Warning>

## Required Header

Include the following header on every request. Replace the placeholder with your actual key:

```
Authorization: Bearer ndapi_live_xxxxxxxxxxxxxxxxxxxx
```

No other authentication headers are required. The `Content-Type: application/json` header is also expected on all POST and PATCH requests, but it is not part of authentication.

## Code Examples

<CodeGroup>

```bash curl
curl --request GET \
  --url https://api.ndapi.io/v1/balance \
  --header "Authorization: Bearer ndapi_live_xxxxxxxxxxxxxxxxxxxx"
```

```javascript Node.js
const apiKey = "ndapi_live_xxxxxxxxxxxxxxxxxxxx";

const response = await fetch("https://api.ndapi.io/v1/balance", {
  method: "GET",
  headers: {
    Authorization: `Bearer ${apiKey}`,
    "Content-Type": "application/json",
  },
});

if (!response.ok) {
  const { error } = await response.json();
  throw new Error(`${error.code}: ${error.message}`);
}

const { data } = await response.json();
console.log(data);
```

</CodeGroup>

## Authentication Error Responses

When authentication fails, the API returns a structured error response in the standard envelope. For example:

```json
{
  "status": "error",
  "error": {
    "code": "INVALID_API_KEY",
    "message": "The API key provided was not found or has been revoked."
  }
}
```

The table below lists all authentication-related error codes:

| HTTP Status | Error Code | Cause | Recommended Action |
|-------------|------------|-------|--------------------|
| `401` | `INVALID_API_KEY` | The key was not found in the system or has been revoked | Check the key value and that it matches the target environment; generate a new key if needed |
| `401` | `MISSING_API_KEY` | No `Authorization` header was included in the request | Add the `Authorization: Bearer <key>` header to every request |
| `403` | `INSUFFICIENT_PERMISSIONS` | The key exists and is valid but does not have the scope required for this operation | Use a key with the appropriate permission scope, or adjust the key's permissions in the dashboard |

<Note>
  API key permissions (scopes) are configured per key in your dashboard. If you need to perform an action that your current key does not allow, create a new key with the required scopes rather than granting excessive permissions to an existing key.
</Note>
