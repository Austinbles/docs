The NDAPI REST API gives you programmatic access to payment infrastructure across Africa — including virtual accounts, transfers, collections, and balance management. Every feature available in the dashboard is also available through the API, letting you build automated, scalable financial workflows for your platform.

## Base URLs

All API requests are made over HTTPS. Use the **production** base URL for live traffic and the **sandbox** base URL when building or testing integrations.

| Environment | Base URL |
|-------------|----------|
| Production  | `https://api.ndapi.io/v1` |
| Sandbox     | `https://sandbox.ndapi.io/v1` |

<Tip>
  Always develop and test against the sandbox environment (`https://sandbox.ndapi.io/v1`) before switching to production. Sandbox transactions do not move real funds and sandbox API keys (`ndapi_test_...`) cannot be used in production.
</Tip>

## Versioning

All endpoints are prefixed with `/v1`. The current version is **v1** and it is the only version available. When NDAPI introduces breaking changes — such as removing a field or altering an existing endpoint's behaviour — a new version (e.g. `/v2`) will be released. You will receive advance notice before any version is deprecated, and both versions will remain available during a migration window.

## Request Format

All request bodies must be JSON. Set the `Content-Type` header to `application/json` on every write request. Authenticate every request by passing your API key as a Bearer token in the `Authorization` header.

```
Content-Type: application/json
Authorization: Bearer <YOUR_API_KEY>
```

All responses are also JSON, regardless of whether the request succeeded or failed.

## Response Envelope

Every API response — success or error — is wrapped in a standard envelope. Successful responses look like this:

```json
{
  "status": "success",
  "data": { ... }
}
```

List endpoints include an additional `meta` object containing pagination information. Error responses replace `data` with an `error` object containing a machine-readable code and a human-readable message. See the [Errors](/api-reference/errors) reference for the full structure.

## Rate Limits

Each API key is limited to **100 requests per minute**. Every response includes the following headers so you can track your current usage:

| Header | Description |
|--------|-------------|
| `X-RateLimit-Limit` | The maximum number of requests allowed per minute |
| `X-RateLimit-Remaining` | The number of requests remaining in the current window |
| `X-RateLimit-Reset` | Unix timestamp (seconds) at which the current window resets |

When you exceed the limit, the API returns a `429 Too Many Requests` response. Wait until `X-RateLimit-Reset` before retrying.

## Idempotency

For all write operations (POST requests that create or modify resources), include a `reference` field in the request body. NDAPI uses this value as an idempotency key — if you send the same `reference` more than once, the API returns the result of the first successful request rather than creating a duplicate. This protects against double-charges caused by network retries.

<Note>
  The `reference` must be unique per operation type within your account. A transfer and a collection may share the same `reference` without conflict, but two transfer requests with the same `reference` will be deduplicated.
</Note>

## Minimal Request Example

The following example fetches your current wallet balance. It requires no request body — only authentication.

<CodeGroup>

```bash curl
curl --request GET \
  --url https://api.ndapi.io/v1/balance \
  --header "Authorization: Bearer ndapi_live_xxxxxxxxxxxxxxxxxxxx"
```

```javascript Node.js
const response = await fetch("https://api.ndapi.io/v1/balance", {
  method: "GET",
  headers: {
    Authorization: "Bearer ndapi_live_xxxxxxxxxxxxxxxxxxxx",
  },
});

const { status, data } = await response.json();
console.log(status, data);
```

</CodeGroup>

A successful response returns your live balance wrapped in the standard envelope:

```json
{
  "status": "success",
  "data": {
    "currency": "NGN",
    "available": 250000.00,
    "ledger": 260000.00
  }
}
```
